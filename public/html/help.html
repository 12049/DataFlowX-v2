Error Codes Reference

Common Error Codes & Solutions

Understanding error codes is essential for debugging your API integrations. Here are the most common errors and how to resolve them:

400 - Bad Request: The request format is incorrect. Check your parameters and JSON structure.
401 - Unauthorized: Invalid API key or insufficient permissions. Verify your API key in headers.
403 - Forbidden: You don't have permission to access this resource. Check your subscription plan.
404 - Not Found: The endpoint does not exist. Verify the URL and endpoint path.
429 - Too Many Requests: Rate limit exceeded. Wait before making more requests or upgrade your plan.
500 - Internal Server Error: Something went wrong on our servers. Try again later or contact support.
503 - Service Unavailable: The service is temporarily down for maintenance. Check our status page.

JavaScript (Fetch API):

async function searchPinterest(query) {
  const API_KEY = 'YOUR_API_KEY_HERE';
  const response = await fetch(
    `https://blackwave-api.vercel.app/api/v1/search/pinterest?query=${encodeURIComponent(query)}&limit=10`,
    {
      headers: {
        'Authorization': `Bearer ${API_KEY}`,
        'Content-Type': 'application/json'
      }
    }
  );
  
  const data = await response.json();
  return data;
}

// Usage
searchPinterest('anime').then(console.log);

Python (Requests):

import requests

def search_pinterest(query):
    api_key = "YOUR_API_KEY_HERE"
    url = "https://blackwave-api.vercel.app/api/v1/search/pinterest"
    
    params = {
        "query": query,
        "limit": 10
    }
    
    headers = {
        "Authorization": f"Bearer {api_key}",
        "Content-Type": "application/json"
    }
    
    response = requests.get(url, params=params, headers=headers)
    return response.json()

# Usage
results = search_pinterest("anime")
print(results)

Common Issues & Solutions:

  • Cannot GET /api/v1/... → Verify the endpoint URL is correct and includes the version (v1)
  • 401 Unauthorized → Ensure your API key is valid and included in the Authorization header
  • Timeout errors → Increase timeout settings or implement retry logic
  • No results returned → Try a different search query or check rate limits
AI Chat Completion Example

Endpoint:

POST https://blackwave-api.vercel.app/api/v1/ai/chat

Request Body:

{
  "message": "Explain quantum computing in simple terms",
  "model": "gpt-4",
  "temperature": 0.7
}

Node.js Example:

const axios = require('axios');

async function aiChat(message) {
  try {
    const response = await axios.post(
      'https://blackwave-api.vercel.app/api/v1/ai/chat',
      {
        message: message,
        model: 'gpt-4',
        temperature: 0.7
      },
      {
        headers: {
          'Authorization': `Bearer YOUR_API_KEY_HERE`,
          'Content-Type': 'application/json'
        }
      }
    );
    
    return response.data;
  } catch (error) {
    console.error('AI Chat Error:', error.response?.data || error.message);
    throw error;
  }
}

Frequently Asked Questions

Common Questions & Answers

Do I need an API key?

Yes But not now; we plan to make some APIS paid in the future.

Is there a request limit per day?

No, but in the future:

Yes, rate limits vary by subscription plan:

  • Free Plan: 100 requests per day
  • Basic Plan: 1,000 requests per day
  • Pro Plan: 10,000 requests per day
  • Enterprise: Unlimited requests

You can check your current usage in the dashboard. Rate limit headers are included in all responses.

Is the API free to use?

We offer a free tier with limited requests for testing and small projects. For production use or higher volumes, we offer paid plans with more features, higher limits, and priority support. Visit our pricing page for details.

Is my data secure?

Yes, security is our top priority:

  • All API communications use HTTPS encryption
  • API keys are encrypted at rest
  • We never store your request data longer than necessary
  • Regular security audits and penetration testing
  • GDPR and CCPA compliant
What if I get a 500 error?

500 errors indicate a server-side issue. Here's what to do:

  1. Wait a few moments and retry the request
  2. Check our status page for ongoing incidents
  3. If the error persists, contact support with:
    • Your API key (masked)
    • The exact endpoint you're calling
    • The request parameters (excluding sensitive data)
    • The timestamp of the error

Tips for Using the API

Best Practices & Optimization

Use Proper Headers

Always include Content-Type: application/json and your Authorization header with the Bearer token for authenticated requests.

Implement Retry Logic

For production applications, implement exponential backoff retry logic for 5xx errors and rate limits.

Cache Responses

Cache API responses when appropriate to reduce requests and improve performance for your users.

Handle Errors Gracefully

Always check response status codes and handle errors appropriately in your application.

Monitor Rate Limits

Check the X-RateLimit headers in responses to monitor your usage and avoid hitting limits.

Use Webhooks

For long-running operations, use webhooks instead of polling to receive results asynchronously.
